# Testing WatchDeck in production

## MANDATORY: QA traffic marking (R245+, 老板口径)
- ALL production HTTP/browser traffic from QA sessions MUST carry `x-qa: 1` request header (or a UA containing `ZalizeQA`). Analytics middleware classifies these as ua_class='qa' and admin /api/stats excludes them (alongside bot/funnel).
- Browser: attach to each page target via CDP and send `Network.enable` + `Network.setExtraHTTPHeaders {"x-qa":"1"}`; the override lasts only while the CDP websocket stays open, so hold it in a background process (see /home/ubuntu/r245_qaheader.py). curl: `-H 'x-qa: 1'`. Scripts using CDP: set the same header per tab.
- Verify with D1: `SELECT path, ua_class, ts FROM analytics_events WHERE ua_class='qa' ORDER BY ts DESC` (analytics logs HTML GETs only, not POSTs/api; the `/` homepage may be edge-cached and not produce a row).

## R246 (Version 0a49e69c) — dual-dimension login rate limit, fail-closed admin, bot classifier
- Login limits: IP `rl:login:<ip>` 15/10min AND per-account `rl:login-acct:<email>` 10/10min; success clears only the acct key. Budget wrong-password POSTs across BOTH dimensions when testing (e.g. 11 on email A → 429 acct-dim; 1 on email B same IP → 401 proves not IP-dim).
- Cloudflare edge WAF blocks non-browser POSTs to /login (plain-text 403 "Forbidden", content-type text/plain, no worker HTML). Fix: send `origin: https://watchdeck.zalize.com` (+referer) headers with curl — then the worker responds normally. GETs are unaffected.
- ua_class: empty UA or /bot|crawl|spider|curl|wget|python|httpie|go-http/i → 'bot'; x-qa/ZalizeQA 'qa' takes priority; else mobile/desktop. Default-curl GETs now land as 'bot' (were 'desktop' pre-R246).
- Admin endpoints (GET /api/stats, POST /api/admin/cron, POST /api/indexnow) are fail-closed 403 for anonymous and non-admin sessions.

## R245 (Version def8870a, CSS/JS v178)
- form[data-validate] invalid submit now focuses first bad input via setTimeout 0 — works for MOUSE clicks too (activeElement=INPUT email, was body before).
- Login rate limit: 15 POSTs / 10 min per IP (KV `rl:login:<ip>`) — shared-egress IPs can hit 429 sooner than your own attempt count suggests; the 429 page is itself a valid role=alert+email-refill branch. Budget wrong-password POSTs and be ready to wait out the 10-min window.
- Leftover CDP-created tabs steal computer-use focus — close them (or navigate to about:blank) before typing into the main tab, else keystrokes go to the wrong page.

## R243 (Version 83798f98, CSS v176 unchanged) — auth server-error a11y
- Server errors on AuthForm/ForgotForm/ResetForm: `<p role="alert" tabindex="-1" data-server-error>`; app.js focuses it on DOMContentLoaded; login/signup error branches refill email (never password); hidden `next` survives the error response.
- CACHE GOTCHA: `/app.js?v=<CSS_VERSION>` — if a round changes app.js WITHOUT bumping CSS_VERSION, the edge (max-age 1h + SWR 24h) and your browser keep serving the OLD app.js under the same ?v= URL. Symptom seen live: role=alert/email-refill (SSR) worked but focus (JS) didn't until a hard reload/`fetch(url,{cache:'reload'})`. Always hard-reload (ctrl+shift+r) before asserting new JS behavior, and flag unbumped versions as a real user-facing propagation delay.
- Reproducing the /login 401 error page at 375px in CDP: fill inputs + `form.submit()` via Runtime.evaluate (remove novalidate first if needed); one wrong-password POST per check, stay far below the 15-attempt rate limit.
- Inline hints (e.g. "✓ Password looks good") shift the submit button down ~15px — re-locate the button before clicking or the click misses silently.
